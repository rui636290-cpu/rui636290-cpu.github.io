# TASK-003-REDESIGN-UX：重构为原创的编辑式求职体验

状态：`APPROVED`

前置任务：`TASK-002-UPDATE-PROFILE.md` 及其返工任务必须完成并由 Codex 复核；本任务未成为根目录 `TASK.md` 的当前任务前不得执行。

## 执行者与目标

Claude Code 是唯一业务代码执行者。执行时必须从磁盘读取根目录 `TASK.md`、本文件、`AGENTS.md` 和 `CLAUDE.md`。

将站点从通用的“科技作品集卡片页”改为原创、克制的求职型编辑体验。目标是让招聘者在 30 秒内看懂：丰瑞是谁、正在寻找什么岗位、已具备哪些可证实的电商业务经验、一个代表项目、以及如何通过邮箱联系。

本任务只重构 UI 与 UX；不得增加或修改用户事实、项目数据、联系方式、依赖、技术栈或部署配置。

## 为什么需要重构

当前实现包含蓝绿渐变按钮、玻璃质感面板、核心能力方格、证据横条、左右大项目卡、流程圆点和大写英文标签。这些组合与参考项目过于相近，也把求职信息拆散成多个重复区块。

## 新体验结构

首页按以下顺序呈现，删除重复模块而非叠加新模块：

1. **简洁顶栏**：姓名文字标识、项目/经历/简历锚点、下载简历、主题切换；不使用图形 Logo 或品牌缩写徽章。
2. **求职首屏**：
   - 眉题：`杭州 · AI 产品方向求职`；
   - H1 以姓名和目标岗位为主，而非口号式多行大标题；
   - 一段 2–3 行的真实业务转型说明；
   - 主 CTA：查看代表项目；次 CTA：邮箱联系；PDF 仍作为明显但非首要入口；
   - 右侧或下方只保留一张“求职名片”：目标岗位、城市、教育、实习时间。不要用能力卡或抽象流程图。
3. **真实证据带**：一个横向的“已确认经历”摘要，仅呈现 1 段天猫运营实习和 1 个市场规划项目，并链接至对应区块；不使用数字指标或进度条。
4. **代表项目**：单个编辑式案例引导块，明确 `问题 / 我的工作 / 已确认产出` 三项，进入完整案例。不要用左右分栏的大封面卡、流程圆点、渐变图或伪数据可视化。
5. **经历**：简洁时间线或左侧日期、右侧内容的履历样式；招聘者可快速扫到公司、岗位、地点、时间和 5 条职责。
6. **关于与教育**：合并成一段简短个人说明及教育信息；不再用“核心优势”多卡片罗列未验证 AI 实战能力。
7. **联系**：邮箱作为唯一真实且可点击的联系通道；未提供的电话、微信二维码、Boss、GitHub 不渲染为可用联系方式。保留 PDF 占位下载的替换提示，但不要把它伪装成真实简历。

项目列表与详情页应继承同一套编辑式阅读层级：标题、背景、职责、方法、已确认产出、边界与后续补充；避免复杂 TOC 卡片和通用作品集视觉。

## 原创视觉语言

- 浅色：暖白/纸张色背景、炭黑正文、低对比灰边线、单一灰紫强调色。
- 深色：深炭背景、暖灰文字、降低强调色饱和度；保留系统主题默认和本地持久化。
- 系统中文字体栈，不加载任何远程字体。
- 使用细分隔线、克制留白、紧凑信息密度和文字层级建立版面；不使用渐变、玻璃模糊、发光、彩色流线、几何装饰或多色状态胶囊。
- 圆角小而克制（最大 10px）；卡片仅在确有信息分组时使用，不能把每段内容都装进卡片。
- 图片缺失时不造视觉，不添加抽象封面；让文字与结构承担信息表达。
- 仅保留轻微的链接/按钮 hover；尊重 `prefers-reduced-motion`。

## 交互与响应式

- 360px、390px：首屏自然高度、无横向滚动、CTA 可触控、菜单可关闭、邮箱可点击。
- 768px 及以上：首屏可使用文字与求职名片双列；代表项目和经历保持清晰阅读宽度。
- 1024px 及以上：正文最大宽度适中，避免通栏长行；不依赖复杂悬浮交互。
- 保留键盘焦点、跳转链接、Escape 关闭菜单、语义标题层级和主题切换。

## 验收标准

- 与参考项目及当前旧版的相似视觉语汇已移除：蓝绿渐变、FR 徽章、玻璃面板、能力方格、证据横条、左右大项目卡、流程圆点、多色状态胶囊。
- 招聘者首屏能看到丰瑞、AI 产品助理/AI 产品经理实习生、杭州、一个真实实习和明确联系入口。
- 页面只呈现 TASK-002 已确认的事实；不因重新设计重新引入未验证项目、数据或联系方式。
- 浅/深色、桌面/移动端、菜单、焦点与减少动画均正常。
- 不引入依赖、远程字体、CDN、图片或运行时 API。
- `npm run build` 通过；使用本地浏览器在 390px 与 1440px 检查首页、项目页、在线简历并修复明显溢出或可读性问题。
