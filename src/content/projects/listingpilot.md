<section id="snapshot">

## 30 秒摘要

ListingPilot AI 面向电商运营人员，解决 Listing 优化中"不知道怎么写更好"的核心痛点。通过结构化 Prompt 和分级 Workflow，帮助运营人员高效完成标题、关键词和描述的优化。当前为产品设计与原型阶段。

</section>

<section id="context">

## 背景与目标

在淘宝、天猫和速卖通等平台的日常运营中，Listing 优化（标题、关键词、描述）是影响搜索曝光和点击转化的核心工作。运营人员通常需要手动研究竞品、收集关键词、根据平台规则调整文案，工作量大且经验依赖度高。

本项目的目标不是替代运营人员的判断，而是通过 AI 辅助，把竞品分析、关键词提取和文案优化变成可复用、可迭代的结构化流程，让运营人员把精力集中在策略决策而非重复性文案工作上。

### 我的职责

- 从自身电商运营经验出发，梳理 Listing 优化的真实痛点和需求
- 设计 Prompt 模板体系，覆盖标题生成、关键词提取和描述优化
- 设计产品原型和核心用户流程
- 推动 Demo 实现并收集反馈

</section>

<section id="research">

## 调研与关键洞察

基于实际电商运营经验，核心发现：

1. **不同平台规则差异大**：淘宝注重销量和店铺权重，速卖通注重标题关键词密度，亚马逊注重合规性——不能用一个通用模型覆盖
2. **关键词不是越多越好**：需要区分核心词、长尾词和场景词，根据类目和价格带选择策略
3. **运营人员需要的是"可解释的建议"，不是"黑盒生成"**：为什么推荐这个词、为什么删掉那个词——解释比结果更重要
4. **类目知识壁垒高**：不同类目的用户搜索习惯、竞争格局和平台规则差异巨大

核心洞察：AI Listing 工具的价值不在于"自动生成"，而在于把运营人员的隐性经验转化为可复用、可迭代的结构化优化流程。

</section>

<section id="reframe">

## 重新定义问题

原问题：如何用 AI 自动生成 Listing？

重新定义后：如何通过结构化 Prompt 和分步 Workflow，让运营人员高效完成标题、关键词和描述的优化，并且每步输出都可理解、可验证？

</section>

<section id="solution">

## 方案与关键决策

### 决策一：分级优化，而非一键生成

将 Listing 优化拆分为标题 → 关键词 → 描述三个阶段，每阶段独立完成并允许人工修改后再进入下一阶段。避免一次生成结果不合格时全部重做的尴尬。

### 决策二：Prompt 结构化模板

每个阶段的 Prompt 包含：平台信息、类目信息、竞品参考、已有内容、当前目标。输出格式固定（JSON 结构），便于前端渲染和人工复核。

### 决策三：平台差异化策略

以平台和类目为维度区分优化策略，例如淘宝标题注重销量词和促销词、速卖通标题注重关键词密度。不做"一视同仁"的通用模型。

### 决策四：当前聚焦产品设计与验证

项目处于早期阶段，优先完成需求分析、Prompt 设计和原型验证。暂不投入完整工程实现，待 Demo 反馈后再决定技术方案。

</section>

<section id="architecture">

## 产品架构（原型阶段）

```text
用户输入（平台、类目、商品信息）
         ↓
   阶段一：标题优化
   （竞品标题参考 + 关键词密度分析 + 平台规则约束）
         ↓
   人工确认 / 修改 → 进入下一阶段
         ↓
   阶段二：关键词优化
   （核心词 + 长尾词 + 场景词 + 搜索量参考）
         ↓
   人工确认 / 修改 → 进入下一阶段
         ↓
   阶段三：描述优化
   （卖点提炼 + 场景描述 + 平台格式适配）
         ↓
   最终输出：完整 Listing（标题 + 关键词 + 描述）
```

当前原型阶段已用文档和 Figma 验证以上流程；Demo 阶段将采用 LLM API + 简单 Web 界面实现。

</section>

<section id="bad-cases">

## 已知边界与风险

- 专业类目术语（如防晒面罩、冰袖等）的 Prompt 效果需要针对性测试和调优
- 不同平台规则更新频繁，Prompt 模板需要持续维护
- LLM 输出的稳定性需要多轮测试验证

</section>
